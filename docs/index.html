2.2 Intelligibility — Round-Trip WER

Whisper large-v3 + EnglishTextNormalizer · 230 sentences Pass on 4 / 5 categories

What: Word Error Rate of a Whisper large-v3 transcript against the reference text used to synthesise. Clean TTS produces audio Whisper transcribes back almost exactly — the rate at which it can't is a proxy for intelligibility.  How: Each reference sentence is synthesised through the REST path, transcribed locally with Whisper large-v3, then compared with jiwer. Both sides are normalised with Whisper's EnglishTextNormalizer, which canonicalises digit↔word, currency, contractions and units so spoken-form references aren't falsely penalised against Whisper's digit-form output.

  • TTFB is nearly flat across input length — first audio arrives in under ~0.5 s whether the input is 10 or 300 words, so time-to-first-audio doesn't degrade as prompts grow. This is the property that matters for responsive streaming.

Clean linear scaling to N=10; the service's rate-limit ceiling appears at N=20.
  • N=1→10 scales cleanly: throughput climbs 0.45 → 2.0 → ~3.7–3.9 RPS with zero errors on both paths and stable per-request latency (~2.5 s). This is the usable concurrency envelope.
  • At N=20 the REST async path hit the rate limit hard — 40 of 50 requests returned HTTP 429 (80% error rate). The reported RPS for that row is not meaningful. The thread-pool path at N=20 stayed error-free but its throughput fell to 2.64 RPS (below N=10), consistent with throttling rather than added capacity.
  • Practical ceiling: keep sustained concurrency at or below ~10 in-flight requests for this key/tier, or add client-side rate limiting and retry-with-backoff to absorb 429s beyond that.
